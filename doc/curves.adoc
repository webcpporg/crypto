[#crypto-curves]
== Curves: `webcpp::crypto::curves`

An *elliptic curve* gives public-key cryptography with short keys: a secret key
is a number, its public key a point of the curve computed from it, and going
back from the point to the number is infeasible. On a curve a program can
*sign*, so that anyone with the public key can check who wrote a message
(link:https://en.wikipedia.org/wiki/Digital_signature[Wikipedia]), and *agree
on a key*, so that two parties who only exchanged public keys share a secret
(link:https://en.wikipedia.org/wiki/Elliptic-curve_Diffie%E2%80%93Hellman[Wikipedia]).

The namespace `webcpp::crypto::curves` holds three curves in this version, the
three columns of the table below. The first is secp256k1 (link:https://www.secg.org/sec2-v2.pdf[SEC 2];
link:https://en.bitcoin.it/wiki/Secp256k1[Bitcoin Wiki]), the curve of
Bitcoin, Ethereum and Nostr. This version covers Bitcoin's keys and signatures,
Nostr's event signatures (NIP-01) and the raw x-coordinate ECDH of its
encrypted messages (NIP-44, <<crypto-secp256k1-ecdh>>), and Ethereum's ECDSA:
recoverable signatures, the recovery of a signer's public key from a
signature, and the uncompressed key (<<crypto-secp256k1-recovery>>). It adds
tweaks to whole keys, the arithmetic of BIP 32's derivation and of watch-only
wallets (<<crypto-secp256k1-tweaks>>), and writes and reads keys in the SPKI and
PKCS#8 files that OpenSSL exchanges (<<crypto-secp256k1-formats>>), and sends
keys as random-looking bytes, BIP 324's ElligatorSwift
(<<crypto-secp256k1-ellswift>>).
Ethereum's `v` encoding of the recovery id, the hash it signs, its
transactions and its addresses are a domain library's. The second is Ed25519,
RFC 8032's signatures on edwards25519, with Ed25519ph for a message given in
pieces (link:https://www.rfc-editor.org/rfc/rfc8032[RFC 8032];
<<crypto-ed25519>>). The third is X25519, RFC 7748's key agreement on
Curve25519, the same curve in another form, with the conversion of an Ed25519
key to it (link:https://www.rfc-editor.org/rfc/rfc7748[RFC 7748];
<<crypto-x25519>>), and libsodium's key exchange on it, `crypto_kx`
(<<crypto-kx>>). A program chooses a curve for compatibility: a signature on one
curve is checked only with that curve, and the curve of passkeys and TLS
certificates, P-256, is another, which this version does not offer. Ed25519's
and X25519's keys leave a program, and enter it, in the standard forms OpenSSL
and WebCrypto use, SPKI and PKCS#8, as DER or PEM text (<<crypto-key-formats>>).
