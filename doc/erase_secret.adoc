[#crypto-erase-secret]
=== Erasing a secret from a buffer

A password read from a form, a key loaded from a file or a plaintext just
decrypted sits in a buffer of the program's own: a `std::string`, a
`std::vector`, an array. Once the program is done with it, the secret should
not stay in memory, where a crash dump, a swapped page or a later bug that reads
freed memory would find it.

`memset` does not do that reliably. A buffer that is zeroed and then never read
again is a dead store, and an optimising compiler removes it: the zeroes are
never written and the secret stays
(link:https://cwe.mitre.org/data/definitions/14.html[CWE-14]).
`erase_secret`, in `<webcpp/crypto/erase_secret.hpp>`, writes through a
volatile pointer and then a signal fence, as `secret<N>` does when it is
destroyed, so the stores are kept:

[source,cpp]
----
include::{library-root}/test/erase_secret_test.cpp[tag=erase,indent=0]
----

It takes any contiguous sized range of elements the program may write and that
are trivially copyable: a `std::vector<std::uint8_t>`, a `std::string`, a
`std::array`, a `std::span<std::byte>`, a C array. It erases
`size() * sizeof(element)` bytes from the first element: a string's size, not
its capacity. A const range, or one of elements that are not trivially
copyable, stops the build with a message naming the ranges it takes; a range
that is not contiguous, such as a `std::list`, has no `erase_secret`. It calls
no backend and never fails.

include::generated/backends-erase_secret.adoc[]

*What it is not.*

* It erases the bytes it is given, and only those. A `std::string` or a
  `std::vector` that grew has left earlier copies in the memory it freed, and a
  copy, a move or a temporary may hold the secret in another object or a
  register: reserve the buffer's size first, and keep the secret in one place.
* It does not lock the memory: the page may still be swapped to disk before the
  call. Locking it (`mlock`, `VirtualLock`) is the program's, and has no
  equivalent on WebAssembly.
* A secret that crypto returns is already a `secret<N>`, which erases itself:
  `erase_secret` is for the buffers the program fills itself.
