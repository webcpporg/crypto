[#crypto-block]
=== The block cipher

A *block cipher* is a keyed permutation of fixed-size blocks: with the key, each
16-byte block maps to one other block and back; without it, the output looks
random (link:https://en.wikipedia.org/wiki/Advanced_Encryption_Standard[Wikipedia];
link:https://csrc.nist.gov/pubs/fips/197/final[FIPS 197]). It is the building
block of every AES mode, GCM's included, and not encryption by itself: applied
to each block of a message alone, equal blocks give equal ciphertext, and the
shape of the data shows through, the mode called ECB
(link:https://en.wikipedia.org/wiki/Block_cipher_mode_of_operation[Wikipedia]).

`aes128`, `aes192` and `aes256`, in `<webcpp/crypto/ciphers/aes.hpp>`, are the
AES block cipher with keys of 16, 24 and 32 bytes. They work in place on whole
blocks: `encrypt` and `decrypt` take a span whose size is a multiple of
`block_size`, 16, and give `invalid_input_size` for a partial block. Each is
made with `make(key_bytes)`, which gives `invalid_key_size` for a key of another size;
an object moved from is wiped and empty, and returns `invalid_state`.

BearSSL exports AES only inside its modes, with no single-block class, so
`aes256<backends::bearssl>` is a complete type, which `gcm` needs to name its
cipher, but its `make` does not compile, and a `static_assert` says which
backends to use (<<crypto-jamfile-messages>>). `aes256<>` is the cipher of
`aes256_gcm`, so it follows AES-GCM's default backend, OpenSSL natively and
BearSSL on WebAssembly, where `aes256<>::make` does not compile: a program that
wants the block cipher there names
`aes256<backends::ctaes>` and includes `<webcpp/crypto/backends/ctaes.hpp>`.
ctaes is a constant-time bitsliced AES, the one Bitcoin Core ships
(link:https://github.com/bitcoin/bitcoin/tree/master/src/crypto/ctaes[ctaes]):
the block cipher alone, which allocates nothing and wipes its key schedule. GCM
is not built on it: webcpp writes no mode of its own on another library's AES.

*Pitfalls.*

* Encrypting several blocks one by one is ECB, and leaks every repeated block:
use AES-GCM for anything longer than one block.
* An opaque reference hides the id; it does not authorise the request. Check
that the order belongs to the user who asks for it.
