[#crypto-jamfile-programs]
== Jamfiles of programs that use crypto

<<crypto-jamfile>> gives the rule: a program names `/webcpp/crypto//crypto`
and the library of each backend it uses. These are the programs of the
`example` directory, with the Jamfile line and what each prints.

[#crypto-jamfile-sign]
=== A program that signs with libsecp256k1

[source,bash]
----
exe sign : sign.cpp /webcpp/crypto//crypto /third_party//secp256k1 ;
----

`sign.cpp` makes a key pair, signs a message with BIP340, verifies the
signature and refuses a changed message. `b2` builds it and `./sign` prints
`schnorr ok`, on native, wasip2, wasip3 and Emscripten.

The precomputed tables of libsecp256k1 are the size knob. On Emscripten the
small tables are the default; natively and on wasip2 and wasip3 the large ones. A
program chooses with the feature `webcpp-secp256k1-tables`, `auto`, `small` or
`large`. The small tables make the program about 1 MB smaller (on Emscripten at -Os, 141,922 bytes instead of
1,211,251) for verifications about a third slower:

[source,bash]
----
exe sign_small : sign.cpp /webcpp/crypto//crypto /third_party//secp256k1
  : <webcpp-secp256k1-tables>small ;
----

`sign_small` prints `schnorr ok` too.

[#crypto-jamfile-encrypt-and-sign]
=== A program that encrypts and signs

A program that uses two backends names both libraries:

[source,bash]
----
exe app : app.cpp /webcpp/crypto//crypto /third_party//bearssl /third_party//secp256k1 ;
----

`encrypt_and_sign` seals a message with `aes256_gcm` and signs it, and prints
`aes256_gcm ok backend=bearssl` and `schnorr ok`.

[#crypto-jamfile-block]
=== A block cipher with ctaes

[source,bash]
----
exe block : block.cpp /webcpp/crypto//crypto /third_party//ctaes ;
----

`block.cpp` encrypts the FIPS-197 appendix C.3 block with AES-256 on
ctaes, checks it, and decrypts it again; `./block` prints `ctaes aes256 ok`.
The default backend is the AEADs' and has no block cipher on WebAssembly, so the
program names ctaes and includes its header. See <<crypto-block>>.
