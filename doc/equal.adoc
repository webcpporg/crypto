[#crypto-equal]
=== Comparing tags

A *timing attack* recovers a secret by measuring how long a program takes to
handle different inputs
(link:https://en.wikipedia.org/wiki/Timing_attack[Wikipedia]). The commonest
target is a comparison: `==` and `memcmp` stop at the first byte that differs,
so they take longer the more leading bytes match. A server that checks a
request's MAC that way tells an attacker, through its response time, how many
bytes of a forged MAC are right; with enough requests the attacker builds a
valid one byte by byte
(link:https://cwe.mitre.org/data/definitions/208.html[CWE-208]).

`equal`, in `<webcpp/crypto/equal.hpp>`, compares in constant time: it reads
every byte, combines the differences without a branch, and its running time
depends only on the length. It takes two Hash2 digests of one size, or two
spans; spans of different sizes compare unequal without reading their contents,
since a size is public. HMAC itself
(link:https://www.rfc-editor.org/rfc/rfc2104[RFC 2104]) is Boost.Hash2's;
crypto adds the comparison that makes it safe to check.

*Pitfalls.*

* Comparing the hex strings of two MACs with `==` brings the leak back.
* Returning early when the lengths differ is fine, since a length is public;
reading the contents first is not.
* A MAC checked after the request has been acted on protects nothing: check
first.
