[#crypto-protecting-secrets]
=== Protecting secrets outside the primitives

A cipher or a curve keeps its own secrets: it compares its tags in constant
time, wipes its keys when it is destroyed and draws what it needs from the
system's generator. A program also handles secrets of its own around them: it
checks a MAC a request carries, holds a key or a password in a buffer, and
draws a token. Four utilities serve that, each named by what it does. They are
at the top of `webcpp::crypto`, beside the rest of the root, with no namespace
of their own, and need no backend: `random_device` reads the system's
generator, and the other three are code of crypto's.

.What each utility guards against
[cols="2,2,5,3",options="header"]
|===
| Utility | Hygiene | What it guards against | Header

| `constant_time_equal`
| timing
| a comparison whose time tells how many bytes of a forged MAC or token are
right
(link:https://cwe.mitre.org/data/definitions/208.html[CWE-208];
<<crypto-constant-time-equal>>)
| `<webcpp/crypto/constant_time_equal.hpp>`

| `erase_secret`
| memory
| a secret left in a buffer the program owns, a string, a vector or an array,
after its use, where a `memset` the optimiser removed did not erase it
(link:https://cwe.mitre.org/data/definitions/14.html[CWE-14];
<<crypto-erase-secret>>)
| `<webcpp/crypto/erase_secret.hpp>`

| `secret<N>`
| memory
| a secret crypto returns outliving its use: it wipes itself when it is
destroyed or moved from
(link:https://cwe.mitre.org/data/definitions/14.html[CWE-14];
<<crypto-secret>>)
| `<webcpp/crypto/secret.hpp>`

| `random_device`
| drawing
| a key, a nonce or a token drawn from a generator an attacker can predict
(link:https://cwe.mitre.org/data/definitions/338.html[CWE-338];
<<crypto-entropy>>)
| `<webcpp/crypto/random_device.hpp>`
|===

[#crypto-secret]
==== Secrets that wipe themselves: `secret<N>`

Every secret crypto gives back is a `secret<N>`, `N` its size in bytes: a key
pair's `secret()`, the shared secret of `agree`, the session keys of
`crypto_kx`, a tweaked secret key, the secret key read from a PKCS#8 file. It
holds its bytes in an array of its own and wipes them, with the volatile stores
and the fence of `erase_secret`, when it is destroyed and when it is moved
from, so that the secret lives in one object and leaves memory with it.

It is not copyable: a copy is asked for by name, `clone()`, and the caller owns
it. `bytes()` gives a `std::span<std::uint8_t const, N>` to read, which a
cipher's `from_key`, a key pair's `from_secret` or an HKDF takes as its input
without a copy (`from_key(session_keys.transmit.bytes())`), and a `secret<N>`
converts to that span where a function takes it. Neither is offered on a
temporary `secret<N>`, whose bytes would be wiped before the span is read: the
program keeps the secret in a variable first.

*What it is not.*

* It wipes its own storage, and only that. A copy of `bytes()` into a string,
  a vector or a log is the program's, to erase with `erase_secret`, and a move
  or a `clone` may leave copies in registers or temporaries that no library
  reaches.
* It does not lock the memory, as `erase_secret` does not: the page may be
  swapped to disk while the secret is in it.
